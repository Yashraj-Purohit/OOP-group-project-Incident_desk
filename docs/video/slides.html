TECHNOLOGY SELECTION

Why this stack - and what we gave up

JavaScript end to end

One language for server, browser and the terminal client, so the command line and web UI share code.

No framework

The OOP design is ours and visible, not hidden behind annotations. Nothing to install.

SQLite

Embedded, transactional, zero setup. Repositories are an interface, so Postgres is a drop-in swap.

Alternatives considered

Spring Boot + PostgreSQL · Django · React + Express + MongoDB. We chose fewer moving parts to demo reliably.

Limitations (honest)

Single process · login throttle is in memory · simulated email · single-node SQLite writes.

If users grow 100×

Stateless API behind a load balancer, Postgres repository, monitor as a separate worker, a real notification queue.

OBJECT-ORIENTED DESIGN

Every concept in the brief, mapped to real code

Encapsulation

Incident keeps all state in #private fields; changes only through guarded methods.

Abstraction

IncidentService hides lifecycle, SLA, assignment and events behind use-case methods.

Inheritance

User → Employee, Technician, Administrator; AppError → 14 errors.

Polymorphism

Interchangeable strategies, channels and states behind one interface.

Interfaces

Abstract bases that throw if unimplemented: AssignmentStrategy, NotificationChannel, repositories.

Composition

An Incident has a state object; services are composed of repositories, engine and bus.

Association / aggregation

Incident ↔ reporter, technician, service, notes, links, audit.

Exception handling

Custom hierarchy: invalid transition, unavailable technician, workload, missing SLA, duplicate…

Collections

Map registries, Set permissions & tokens, indexed SQL queries.

SECURITY & ERROR HANDLING

Enforced on the server, not in the screen

  • Passwords hashed with scrypt, random salt
  • Random 256-bit session tokens, stored hashed, 8 h expiry
  • Role permissions checked in domain & services
  • Employees cannot see others' incidents (404)
  • Login throttling · input validation · parameterised SQL
  • CSP, Host check, same-origin API, escaped output

All 12 failure cases in the brief are typed errors

Invalid login · unauthorised · invalid incident · invalid state transition · technician unavailable · workload exceeded · service not found · missing SLA · duplicate · database failure · network failure · invalid input
